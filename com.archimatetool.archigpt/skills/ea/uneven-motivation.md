Reply with ANALYSIS (plain text) only. Do not output CHANGES JSON. Use only the supplied XML.

First find core elements (process, service, application, capability, or component) that already have Realization or Association to a Goal, Outcome, Requirement, Principle, or Driver. That is the convention.

Then list peers of that same type on the same view, or in the same folder if no view is in scope, that have no such motivation link.

If no motivation elements are linked to core elements, say that pattern is not modelled and stop. Do not require a motivation layer for the whole model.

Cite type, name, and id. Contrast each gap with a linked example.

Report format:
1. Convention found (examples with ids)
2. Peers with no motivation link
3. Not applicable (if the convention never appears)
